What makes it different

RBAC at the vector layer

Org + clearance + role enforced as a Qdrant must-filter on every search. Dense and sparse vectors share the same payload filter — cross-tenant bypass is structurally impossible from the application layer.

Sensitivity-based inference routing

HIGH-classified documents force local Ollama inference; LOW can opt into Groq / OpenAI / Anthropic. Routing decision per request, provenance recorded in the audit trail.

NLI per-sentence faithfulness gate

Every cited sentence must be entailed by its source chunk under an NLI model. Citation marker presence is not enough — unsupported claims are annotated or dropped.

SHA-256 hash-chained audit

Every request gets a tamper-evident audit entry. PII redacted before persist with provider-specific key shapes (Groq, OpenAI, Anthropic, HF, Vercel, Qdrant JWT). Verifier detects any insertion / deletion / edit.

Try it in 30 seconds

  1. Open the demo: app.eilm.live
  2. Pick a persona: Engineer, Compliance, or Executive — clearance level and roles set per persona.
  3. Ask the same query across personas: e.g. “What does the Q3 finance report say about cash position?” Engineer is blocked by the role allowlist; Compliance and Executive get cited answers with a sensitivity disclaimer attached.
  4. Optional — paste your own LLM key: the BYOK drawer accepts Groq / OpenAI / Anthropic / Ollama URL. Your key lives in localStorage only, never persists server-side, never goes to telemetry.

No key pasted → the demo uses the platform owner's Groq key, throttled to 3 requests per IP per hour (free-tier protection).
